# Running ECA sandboxed in Docker on macOS (Emacs)

Run the ECA server in a Docker container on macOS and use it from Emacs. Auth is a provider `/login` done on the host and copied into the sandbox (steps 4–5), or an API key read from netrc via `keyRc` (step 10). Private GitHub repos work over HTTPS via an optional `GH_TOKEN`. The image has `gh`, `just`, Node.js/npm/Yarn, and `uv` (which also provides Python).

Save the files below under your home directory, outside any workspace, so the agent cannot read or change them through the mount.

## Files on the host

- `~/eca-sandbox/Dockerfile` — image definition (step 2).
- `~/eca-sandbox/copy-login.sh` — copies the host login state into the sandbox cache (step 5).
- `~/.local/bin/eca-sandboxed` — wrapper that Emacs starts instead of `eca` (step 7).
- `~/.config/eca/` — your global ECA dir (config.json, AGENTS.md, skills, commands, agents), mounted read-only (step 6).
- `~/.cache/eca-sandbox/db.transit.json` — copy of the ECA login state, mounted writable (step 5).

The wrapper mounts the directory Emacs starts it in (same absolute path), plus `~/.config/eca` read-only, your `~/.netrc` read-only (if it exists), and the sandbox cache writable.

## Setup

### 1. Directories

```bash
mkdir -p ~/eca-sandbox
mkdir -p ~/.cache/eca-sandbox
chmod 700 ~/.cache/eca-sandbox
```

### 2. Dockerfile — `~/eca-sandbox/Dockerfile`

```dockerfile
FROM ghcr.io/editor-code-assistant/eca-sandbox-image:latest
# The base image already contains eca, git, curl and ripgrep.

RUN apt-get update \
    && apt-get install -y --no-install-recommends \
        ca-certificates \
        gh \
    && apt-get clean \
    && rm -rf /var/lib/apt/lists/*

# Node.js, npm, npx from the official image. Debian variant only — Alpine is musl-based and
# will not run on this glibc base. `lts` is re-pulled on every `docker build --pull`;
# use e.g. node:24-bookworm-slim for a specific Node major.
COPY --from=node:lts-bookworm-slim /usr/local /usr/local

# Yarn via corepack (installed from npm: Node 25+ no longer bundles it).
# `prepare --activate` downloads the latest stable Yarn at build time.
# For Yarn 1 classic instead: npm install -g yarn@1.
RUN npm install -g corepack \
    && corepack enable \
    && corepack prepare yarn@stable --activate

# uv/uvx from Astral's image, per the uv Docker guide; `latest` is re-pulled by --pull.
COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /usr/local/bin/

# uv owns Python: latest stable CPython at build time (add --default for python3/python
# shims). Install it before `uv tool install` so tool envs reuse it instead of downloading
# a second interpreter. Another Python version is downloaded at runtime if a project needs it (network).
RUN uv python install

# just (command runner) via uv, per the just docs: `uv tool install rust-just` (PyPI package
# rust-just, home page github.com/casey/just). UV_TOOL_BIN_DIR puts the executable on PATH
# (/usr/local/bin); the default ~/.local/bin is not on PATH in the container.
# Alternatives: the official GitHub release binary, or `apt install just` on Debian 13+ bases.
ENV UV_TOOL_BIN_DIR=/usr/local/bin
RUN uv tool install rust-just

# Per-project Linux venvs: a relative path resolves against the project root, so several
# repos under the mounted folder each get their own .venv-linux and can be worked on at the
# same time. The host's macOS .venv is never used or modified.
# Add `.venv-linux/` to .git/info/exclude (or a global gitignore) on the host.
ENV UV_PROJECT_ENVIRONMENT=.venv-linux
```

Notes:

- One `RUN` for update+install+clean keeps the layer small; the deleted package lists are regenerated by the next `apt-get update`.
- Never put credentials in the Dockerfile (no `ENV`/`ARG`/`COPY` of tokens) — image layers and build history keep them.
- Pinning: for repeatable builds replace `eca-sandbox-image:latest` with a version tag (e.g. `eca-sandbox-image:0.152.0`) or a digest. `uv:latest`, `node:lts-bookworm-slim` and `yarn@stable` are intentionally unpinned — `--pull` and `corepack prepare` refresh them on every build — and `just` comes from PyPI (`rust-just`, via `uv tool install`) at build time. The only Debian package left is `gh`, which follows the base image's Debian release.

### 3. Build the image

```bash
docker build --pull -t eca-sandbox-local:v1 ~/eca-sandbox
```

`--pull` refreshes the tags in `FROM` and `COPY --from`. Use a new local tag (`v2`, `v3`, ...) per rebuild. Note that `docker run` never pulls — it uses the local image as-is — so to always run the latest ECA, the wrapper rebuilds with `--pull` on every start (step 7); the build cache is keyed on the base image digest, so a moved `latest` rebuilds automatically. If you pin the base tag (step 2 notes), this intentionally stops tracking new ECA releases. Old local images can be removed with `docker image prune`.

### 4. Log in to your provider on the host

The browser `/login` flow does not work inside the container, so log in with the normal host ECA first: default server in Emacs, `/login`, choose your provider, finish the browser flow.

### 5. Copy the login state into the sandbox cache

Save this as `~/eca-sandbox/copy-login.sh`, run `chmod 700 ~/eca-sandbox/copy-login.sh`, and run it after a host `/login` (step 4) and on every re-login:

```bash
#!/usr/bin/env bash
# Copy the host ECA login state into the sandbox cache (atomically: temp + rename).
# Run after a host login. Safe while the sandbox runs as long as no host ECA process
# is left running on ~/.cache/eca afterwards (e.g. quit the eca-cli once logged in).
set -euo pipefail

src="${HOME}/.cache/eca/db.transit.json"
dst_dir="${HOME}/.cache/eca-sandbox"
dst="${dst_dir}/db.transit.json"
image="${ECA_SANDBOX_IMAGE:-eca-sandbox-local:v1}"

if [ ! -f "${src}" ]; then
  echo "copy-login: ${src} not found — run /login with the host ECA first (step 4)" >&2
  exit 1
fi

if docker ps --format '{{.Image}}' | grep -qx "${image}"; then
  echo "copy-login: note: a sandboxed ECA container (${image}) is running — that is fine." >&2
  echo "copy-login: just make sure no host ECA process (server or eca-cli) stays running" >&2
  echo "copy-login: on ~/.cache/eca after this copy; two live refreshers break the token." >&2
fi

cp "${src}" "${dst}.tmp"
chmod 600 "${dst}.tmp"
mv "${dst}.tmp" "${dst}"
chmod 700 "${dst_dir}"
echo "copy-login: copied ${src} -> ${dst}"
```

Then stop the host ECA and switch Emacs to the wrapper (step 8). From then on use only the sandboxed ECA. Never run a persistent host ECA and the sandbox at the same time. OAuth refresh tokens are single-use and the two caches cannot coordinate: if two live processes refresh the same token copy, whichever goes first invalidates the other (`invalid_grant`). Why: the login state contains an OAuth refresh token, and refresh tokens are single-use.

### 6. Global config, skills, commands, agents — shared via read-only mount

Nothing to copy: the wrapper mounts your real `~/.config/eca` read-only at `/root/.config/eca`, so the sandboxed ECA uses the same `config.json`, `AGENTS.md`, `skills/`, `commands/`, `agents/` and rules as the host. Read-only means the agent can read them but not modify them.

### 7. Wrapper — `~/.local/bin/eca-sandboxed`

```bash
#!/usr/bin/env bash
# Start the ECA server inside the sandbox image with the current directory mounted.
set -euo pipefail

image="${ECA_SANDBOX_IMAGE:-eca-sandbox-local:v1}"
workdir="${PWD}"
cache_dir="${HOME}/.cache/eca-sandbox"

for dir in "${cache_dir}"; do
  if [ ! -d "${dir}" ]; then
    echo "eca-sandboxed: missing directory ${dir}" >&2
    exit 1
  fi
done

mount_args=(-v "${workdir}:${workdir}")
if [ -f "${HOME}/.netrc" ]; then
  # Mounted at /root/.netrc because the container runs as root; read-only is enough.
  mount_args+=(-v "${HOME}/.netrc:/root/.netrc:ro")
fi

env_args=()
if [ -n "${GH_TOKEN:-}" ]; then
  env_args+=(-e GH_TOKEN)
fi

# Rebuild with --pull before running, so a newer base image (new ECA) or a Dockerfile
# change is picked up; the build cache makes this a no-op when nothing changed.
# Build output goes to stderr because stdout is the protocol channel. On failure
# (e.g. offline) fall back to the existing local image. Set ECA_SANDBOX_AUTO_UPDATE=0 to skip.
if [ "${ECA_SANDBOX_AUTO_UPDATE:-1}" = "1" ]; then
  docker build --pull -q -t "${image}" "${HOME}/eca-sandbox" >&2 \
    || echo "eca-sandboxed: rebuild failed, using existing image ${image}" >&2
fi

# The ${arr[@]+...} form keeps an empty array safe under `set -u` in macOS's bash 3.2.
exec docker run -i --rm \
  "${mount_args[@]}" \
  -w "${workdir}" \
  -v "${HOME}/.config/eca:/root/.config/eca:ro" \
  -v "${cache_dir}:/root/.cache/eca" \
  ${env_args[@]+"${env_args[@]}"} \
  "${image}" \
  bash -c 'if [ -n "${GH_TOKEN:-}" ]; then gh auth setup-git --hostname github.com --force >/dev/null || exit 1; fi; exec eca "$@"' eca "$@"
```

```bash
chmod 700 ~/.local/bin/eca-sandboxed
```
### 8. Point Emacs at the wrapper

```elisp
(setq eca-server-command '("/Users/<you>/.local/bin/eca-sandboxed" "server"))
(setq eca-send-process-id nil)
```

`eca-send-process-id nil` is required: ECA exits when the editor's process disappears, and the container cannot see host processes. Open the workspace root you want the agent to see (that is what gets mounted), then restart the ECA server in Emacs.

## Re-login

Only when the sandbox reports the provider login expired or invalid (e.g. `invalid_grant`):

1. Stop the sandboxed ECA in Emacs.
2. Use `eca-cli` that isn't running in a sandbox.
3. Run `~/eca-sandbox/copy-login.sh` (step 5).
4. Stop the host `eca-cli`.
